CATALOG PRESERVATION — HARD SAFETY RULE
==================================================

The existing idea catalog is append/update-only for radar runs.

Before any catalog write:
- read the current state/idea_catalog.json;
- preserve EVERY existing idea record and canonical_key;
- a radar run may append new ideas or materially update a matching existing idea;
- a radar run must NEVER delete, truncate, replace, archive, hide or omit an existing
  catalog idea merely because it was not rediscovered today;
- never rebuild the catalog from only today's results.

For the 2026-09-28 run specifically, seven existing catalog ideas are protected.
A safety backup exists at:
state/backups/2026-09-28-idea_catalog.json

If a proposed write would reduce the catalog idea count below the count that
existed at run start, ABORT THE CATALOG WRITE and mark the run:
CATALOG_PRESERVATION_FAILED

Do not publish a completed run until the preservation check passes.

   quality_research_needed_count=0, blockers empty, allow_catalog_write=true;

    may NOT be silently treated as qualifying or as a completed publication gate.

STRICT QUALITY EVIDENCE LOCK — USER REQUIRED

TÜRKÇE İÇERİK NORMALİZASYONU — HARD PUBLICATION GATE
==================================================

AIStartup kullanıcı arayüzünde gösterilen içeriklerin ana dili Türkçedir.
Her yeni veya güncellenen idea_catalog kaydı GitHub'a yazılmadan ÖNCE aşağıdaki dil kontrolünden geçmelidir.

- Kullanıcıya görünen normal iş ve operasyon dili doğal, sade ve anlaşılır Türkçe olmalıdır.
- İngilizce yalnızca sektörde yerleşik teknik terim ve kısaltmalarda kalabilir: AI, LLM, RAG, API, SaaS, MVP, Agent, Agentic AI, workflow, dashboard, SLA, SEO, BESS, CPO, EPC, QR, DNS, CNAME, JSON, CLI, schema, hash ve benzeri gerçekten teknik terimler.
- target_customer, buyer, core_idea, user_story, before_state, after_state, why_now, market_gap, mvp, working_logic, scope_reason, business_models açıklamaları, technologies purpose/cost açıklamaları, marketing_strategy, first_customer_plan, main_risk ve validation_assumption alanlarında sıradan İngilizce iş cümleleri veya İngilizce görev tanımları bırakma.
- İngilizce kaynak başlıkları, şirket/ürün isimleri, URL'ler, canonical_key ve teknik identifier'lar aynen korunabilir.
- User Story Türkçe ve doğal olmalı. "Bir local service business olarak standardize intake..." gibi karma cümleler YASAKTIR.
- Teknik terim Türkçe açıklama içinde ilk kez geçtiğinde gerekiyorsa kısa Türkçe bağlam ver.
- Çeviri kelime kelime değil, anlamı koruyan doğal Türkçe olmalıdır.

PUBLICATION LANGUAGE GATE:
Catalog write öncesinde kullanıcıya görünen yukarıdaki alanların tamamını tara. Teknik terimler ve özel isimler dışındaki belirgin İngilizce cümle/parçalar varsa yayınlama; önce Türkçeleştir. Bu gate başarısızsa run tamamlandı/published sayılmaz.
