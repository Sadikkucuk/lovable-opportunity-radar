MULTI-WORKER RADAR — MERGE / CANDIDATE BUILDER

Repository: Sadikkucuk/lovable-opportunity-radar
Use Europe/Istanbul date for state/runs/YYYY-MM-DD.

Read:
- docs/batches/index.json
- state/runs/YYYY-MM-DD/discovery/worker-1.json
- worker-2.json
- worker-3.json
- worker-4.json
- state/idea_history.json
- CHATGPT_RADAR_PROMPT.txt for productization/feasibility definitions.

FIRST APPLY A HARD COVERAGE GATE.

Expected assignments:
worker 1 = batches 1-6
worker 2 = batches 7-12
worker 3 = batches 13-18
worker 4 = batches 19 through final batch (normally 25)

If ANY worker file is missing, status != complete, assigned batches are wrong,
or the sum of feed_items_triaged != docs/batches/index.json total_items:
- write state/runs/YYYY-MM-DD/merge/status.json with status="blocked_incomplete_discovery"
- include exact missing/failed workers and coverage
- DO NOT create a completed candidates file
- STOP.

If discovery coverage is complete:

1. Merge all raw opportunities.
2. EVENT CLUSTER duplicate/syndicated developments across sources. Preserve all
   supporting sources but do not let one event create duplicated product candidates.
3. SEMANTIC IDEA DEDUPE using:
   target customer + core JTBD + product mechanism/workflow.
   Product name/headline/date alone never makes a new idea.
4. Perform dataset-wide cross-article combination discovery using all raw ledgers.
   LOCAL SIGNAL PRESERVATION: when raw opportunities contain a trakya_transferability_hypothesis,
   Lüleburgaz scope_hint, or concrete Trakya/Lüleburgaz industrial evidence, preserve that
   evidence through semantic dedupe. If a local and non-local raw opportunity collapse into
   the same semantic candidate, union their local evidence; never discard it merely because
   the canonical candidate came from a global/Türkiye article. Local evidence does not make
   two otherwise identical ideas semantically distinct.
5. Apply productization test.
6. Apply zero-external-cash MVP feasibility and <=500 Lovable-credit internal
   feasibility constraint. Explore free/open-source/public-data substitutes before rejection.
7. Pre-match each candidate against state/idea_history.json, but do NOT suppress it
   from validation; mark likely history matches so the finalizer can decide after evidence.
8. Assign deterministic validation_index 1..N after sorting by canonical_key.
   Odd indexes belong to validator A; even indexes to validator B.
9. Do NOT perform final direct-competitor research here.
